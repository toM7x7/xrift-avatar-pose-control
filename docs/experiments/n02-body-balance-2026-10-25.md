# N02：首だけで振り向かず、足場へ踏ん張る身体

2026-10-25。ユーザーの「身体が真横で首だけ90度は人間らしくない」「胸・腰・足の踏ん張りと前進を身体で表したい」という指摘を受けたローカル実験。ここでの角度は表現の初期方針であり、医学的な可動域や人体適合規格ではない。

## 変更前と今回の方針

以前は腰・胸・首を同じ90度横向きにして頭の世界回転だけを戻していたため、振り向きが頭の親付近へ集中していた。さらに足首の目標を毎回腰から生成しており、支持物をその下へ表示するだけでは固定した足場で荷重移動する実験にならなかった。

今回の既定は、足の向き62度、骨盤50度、胸20度、首8度、頭0度。頭が見ている方向へ胸も適応し、骨盤と胸の差は初期方針として45度までとする。大きな振り向きでまだ首へ無理が残る場合は頭の入力を勝手に変えず、neckPolicyExceededとhead-torso-yaw-conflictを出す。

向きは骨のローカルZを全モデル共通の顔前方と仮定せず、inverse-bindとrestBasisから身体の解剖学的な座標系へ変換して測る。腕は改善済みの前低・後高・掌下を保ち、骨盤ではなく胸の座標系へ追従する。

## APIと責務

```js
applyNimbusPose(rig, {
  anchorMode: 'support',
  // 左右の足首を置く固定の世界座標。入力配列やVector3は変更しない。
  footTargetsWorld: [leftAnkleTarget, rightAnkleTarget],
  supportSoleOffsetM, // 実足裏計測から得た足首〜接触面の高さ差。
  balance: {
    leanForward, leanSide, // rad。正は進行方向前、進行方向の右。
    crouch,
    centerOfMassOffset: { forward, side }, // m。足目標中央からの水平目標。
    loadRatio: { front, rear },
    forwardAcceleration, lateralAcceleration // m/s²。
  }
})
```

- `anchorMode:'head'`がAPIの既定。従来どおり頭の位置と回転を保つ契約を維持し、身体の向きは新しい分散姿勢へ更新する。COM目標へ届かない場合は誤差を返す。
- `anchorMode:'support'`では頭の世界回転を保ち、腰を動かして両脚IKを解く。頭位置は身体とともに動き、その移動量をheadDriftMmで正直に表示する。カメラは操作しない。
- 明示した足目標は腰や頭の動きから再生成しない。目標未指定の最初の呼び出しで足目標を得て、利用側が雲のローカル座標に保存し、その後は雲の移動・回転だけで世界座標へ運ぶ。
- `supportHeight`は明示足目標がない場合の足首平面。明示足目標の高さを上書きしない。足裏や靴底の表示補正は別の計測とする。
- `supportSoleOffsetM`は足裏計測後の接触面補正。0〜脚長の0.35倍へ制限し、足IKの目標は足首のまま、COM高とZMPを求める接触面のみ`足首平面 - 補正値`へ置く。contactPlaneY / contactPlaneSourceで使った面を報告する。未計測の最初は足首面で代用し、そのことを示す。
- Vehicle移動・入力・カメラ・衝突・同期はこのコアの担当外。加速度から平衡・慣性を求めるride-dynamicsと、姿勢を実際に変えて検査するこのコアを分ける。

## どのように身体を支えるか

胸と骨盤の回転を分散させ、加減速・旋回の傾斜を分配する。足は固定目標に置いたまま、腰の水平位置と高さを変え、両脚の骨長を保った2節IKで膝を曲げる。前後荷重目標は左右の膝曲がりの目安へ差を付けるが、その角度を実現できたと仮定せず、実測膝角と指定膝角の差を返す。

支持優先では骨点の位置に重みを付けたCOM proxyを計算し、腰の水平移動を最大5回反復して指定した水平COM目標へ近づける。極端な目標は都合よく消さず、残差と足の到達不足を報告する。骨点の重みは腰0.20、胴0.30、頭0.08、左右それぞれ上腕0.03・前腕0.02・腿0.09・下腿0.06・足0.01の合計1.0。実アバターの質量・服・髪を測定した値ではない。

実際に変形した骨点のCOM proxyと加速度から、水平ZMP proxyを`COM水平位置 - COM高 / g * 加速度`で計算する。前後の足首線への投影から前後荷重proxyを求め、要求荷重比との差も残す。足周囲の矩形proxyを結ぶ凸包に対し、ZMPの支持余裕と外れを測る。これは接触力や摩擦を解く完全な剛体・人体シミュレーションではない。

## 観測値

- bodyBalance：腰・胸・足のyaw、頭と胸のyaw差、腰と胸の差、首の残りyaw、首方針の未達、腰の世界位置、傾斜。
- feetWorld / footTargetsWorld：実際の足首と固定目標。footTargetErrorMmは3D距離、contactPlaneErrorMmは目標との高さ差。
- balanceProxy：骨点COM・目標COM・実現した水平offset・未達距離、ZMP、実測荷重proxyと要求比の差、支持余裕、支持域外フラグ。
- knees / requestedKneesDegrees：左右の実測と目安。足目標に届いたことと、希望した膝角になったことを分ける。
- poseLimitReasons：足の到達不足、膝角差、頭と胴の振り向きの競合、COM未達、支持域外を記録する。

## 自作骨格での前後と検証

標準骨格・静止・支持優先では腰50度／胸20度／首残り8度となり、腰と胸の差30度を確認。頭の回転差はほぼ0。初版の頭位置移動は約33.56mm、腰高さの平均化後は約32.92mm。平均化後の膝は約66.30度／67.70度、両足首誤差は0.001mm未満、COM proxyと水平目標との差は約0.00065mm。

同じ固定足目標で前向き傾斜0.15rad・COM目標前80mmを与えると、腰Zは約+56.6mmへ、膝は約67度／88.9度へ変化。逆向きの制動条件では腰Zは約-86.6mm、膝は約86.4度／67度。足首誤差は0.001mm未満で、足場を逃がさず両脚の曲がり方が変わる。

`node --test tests/nimbus-pose.test.mjs tests/nimbus-body-balance.test.mjs`：18件成功。`npm run typecheck`も成功。

追加の7条件は、3体格のyaw分散、固定足での加速・制動・左右旋回、頭優先との比較、大きな頭回転の未達、遠すぎる足／COM目標、実姿勢COMと加速度から求める支持外れ、足裏補正による接触面とZMPの整合を確認する。足目標配列の非変更・骨長維持・頭回転保持も検査する。旧90度の身体を期待したテストと旧世界X方向に固定した腕のテストは、新しい身体／胸座標系の条件へ更新した。

## 残る問題と統合時の注意

ダイナミクスのCOM高を一律0.9mとして、実姿勢のCOM proxy高が約0.63mの自作骨格へそのまま適用すると、COM目標と必要荷重の大きさが合わない。独立観察では片脚が120度超まで曲がる条件が出た。利用側で初期姿勢のCOM高・足場幅を校正し、まず小さい推進・制動から確認する。数値上COMと足目標へ届いていても、その膝の潰れ方が見た目に適切とは限らない。

統合側で足裏平面まで含めたCOM高を約0.6923mへ校正し、推進2.2m/s²・制動3m/s²の条件へ調整した後、自作骨格のブラウザ10条件が成功した。前進中の膝は約68.68度／93.58度、制動時は約101.94度／75.46度。首残りは約8度、足首目標誤差は浮動小数点誤差、水平COM目標との差は最大約0.007mm。これらは統合側のローカル記録を独立に読み直して確認した数値で、実VRMの見た目の合格を代用しない。

実VRMの制動画像で、初版の腰高さを低い側へ合わせる方式では115〜120度まで膝が曲がり、空気椅子へ座り込む印象が残った。独立観察でも同じ指摘があったため、腰高さを両脚の希望高さの平均へ変更し、表現上の膝上限を既定100度とした。`maxKneeDegrees`で75〜125度の範囲に変更できるが、医学的な可動域ではない。

固定足に対して両脚が上限を守れる腰高さの区間を求め、COMに近づける水平移動がその区間を失う場合は移動量を減らす。足と骨長を優先し、残るCOM目標差と膝目標差を表示する。極端な足目標そのものが両立しなければknee-policy-conflictも報告する。bodyBalanceのhipHeightPolicy / maxKneeDegrees / kneePolicyExceeded / hipBalanceLimitedで判断できる。

追加回帰では固定した同じ足目標のままCOMを前後150／200mmへ動かし、膝が100度を超えず、足首誤差0.001mm未満、COM誤差0.1mm未満であることを確認。前600mmという大きなCOM目標と上限95度の競合では、足を動かさず膝上限を守り、COM残差100mm超とhipBalanceLimitedを出す。無理な目標を達成済みとしない。

## 最終の実VRM比較

腰高さの平均化・膝の表現方針と、現在のCOM高をダイナミクスへ緩やかに戻す処理を統合した後、A01/A03の静止・加速・制動・左右旋回を3方向ずつ計30枚撮影した。代表6枚をこの担当も独立観察し、制動で腰が膝近くへ沈む「空気椅子」の印象が弱まり、一方の脚を伸ばして支える形へ改善したことを確認した。胸と腰の向きの差、頭の自然な前向き、掌下の腕線も保たれている。

実VRMはこの2体でのローカル比較であり、見た目の最終採用判断はユーザーの確認を受ける。初版・深すぎた制動版・最終版の画像とJSONは私有の比較記録として残す。統合側では全78テスト・型・ビルド、ブラウザの新規10条件と旧比較22条件の成功を確認している。
