# N02：傾斜した支持面に乗る身体

2026-10-25。水平の足場だけを仮定していたN02を、pitch・bankを持つ雲の支持面へ拡張したローカル実験。足場の見た目や移動をこのコアで生成するものではない。通常飛行で頭の世界回転を保ち、宙返り・背面は扱わない。

## 入力契約

```js
applyNimbusPose(rig, {
  anchorMode: 'support',
  supportFrame: {
    position: cloudContactCenterWorld, // Vector3 または [x,y,z]
    quaternion: cloudRotationWorld   // Quaternion または [x,y,z,w]
  },
  footTargetsWorld: [leftAnkleWorld, rightAnkleWorld],
  supportSoleOffsetM,
  balance
})
```

supportFrame.positionは雲の接触面中心、local+Yは面法線、local+Zは進行、local+Xは右。quaternionは有限・非ゼロを検査して正規化する。左右足首目標は呼び出し側が雲の同じローカルアンカーから世界座標へ運び、コアはその目標を移動させない。

frame指定時のyawはquaternionに含まれるため、headingを二重適用しない。balanceの前後・左右加速度、COM offset、傾斜応答は支持面の接線座標で渡す。有効重力と荷重比も法線射影した値を使う。従来の水平yaw基準の実加速度をそのまま渡すと、傾いた面での重力成分が抜ける。

supportFrameを指定しなければ従来の水平コア経路を使う。headingや水平加速・上下荷重の既存の意味を保ち、追加計測だけを付ける。

## 座標変換と復元

既存の支持solverを支持面ローカル座標で使う。対象骨格の腰とその子孫を一時的に逆frameへ置き、頭・手の姿勢も同じ座標へ移るようにしてから、固定足・骨長・COM・膝方針を解く。結果を世界へ戻してから描画へ渡す。カメラやシーン全体・他のアバターのrootを変換しない。

頭・足・足目標・腰・腕・COM・ZMPのWorld位置、掌法線・指方向のWorld方向をすべて戻す。エラー時は保存した骨のローカル変換へ戻して再送出する。通常の描画終了や入れ子描画での復元は既存のattachPoseDriverが担当する。

frame内のcontact planeはlocalY=0。COM高はその面の法線方向の距離となる。frame指定時のcontactPlaneYは面原点の世界Yであり、傾いた面のどこでも同じ高さという意味ではない。面上の点を調べるときはoriginWorldとnormalWorldを使う。

## 胸・腰・首の追従

足裏のbind基準法線は雲の法線に合わせる。腰・胸・首を雲へ一枚板のように固定せず、物理leanを適用した後の身体upを、重力のworld-upへ一部だけ寄せる。初期方針は骨盤30%・胸65%・首85%。頭は元のworldQを保つ。

この補正は実際のplatform tilt成分に限定する。水平なframeで既存の加速度leanを打ち消したり、既にworld-upになった胸をさらに逆方向へ倒したりしない。これらの分配は見た目の方針であり、人体の剛性や医学的可動域のモデルではない。

足の到達不足・COM残差・膝上限・首yawの競合は従来どおり表示する。頭優先モードは頭の世界位置も保ち、傾斜足場との競合を足の誤差として残す。

## 計測

| 計測 | 意味 |
|---|---|
| supportFrame | originWorld / normalWorld / rightWorld / forwardWorld / 正規化quaternion |
| headAnatomicalUpWorld / headUpDotWorld | 最終世界座標での解剖学的な頭upとworld-upの内積 |
| upright / uprightSupport | 頭と腰を結ぶ方向のworld-up成分／支持法線成分。旧uprightのworld-up契約を保つ |
| headRotationErrorDegrees | 入力頭のworldQから変えていないか。頭入力自体がbankしていないかは上のup計測で別に確認 |
| supportNormalWorld | 支持面の世界法線 |
| feetSupport | bind足法線、支持法線との角度差、足首の法線高さ、足裏オフセットを引いたgap proxy |
| footSoleNormalErrorDegrees | 左右のbind足法線の角度差。実skinの平面推定ではない |
| contactPlaneErrorMm | 固定足目標からの法線方向の誤差 |
| ankleHeightSpreadMm | 左右足首の世界Y差。bank時は正当に増える |
| ankleNormalHeightSpreadMm | 支持法線方向での左右足首の高低差 |
| balanceProxy.comHeightM | COMの面法線高。世界高度から独立 |
| balanceProxy.footHullWorld | 支持域proxyの世界頂点 |

footHull2D、COM offset、lean、bodyBalanceの相対yaw/pitchは支持面座標として明示する。Worldという名前の点・方向は世界座標へ戻す。手のpalmDownDotはworld-down、palmSupportDownDotは支持面downへの成分を分ける。

## 自作骨格での確認

pitch0.2rad・bank0.3radでは面法線は約[0.2955,0.9363,-0.1898]。頭world-up内積1・頭回転差0、左右足法線角度差と足裏gap proxyはほぼ0。骨盤upのworld-up内積は約0.969、胸は約0.992となり、胸のほうがworld-upへ近い。

`node --test tests/nimbus-tilt.test.mjs`：9件成功。型チェックも成功。

1. 小型・標準・大型、pitch／bankの正負、20度／25度で足支持・頭up・骨長・膝方針を確認。
2. 同じ傾斜で高度100m・yaw0.7radへ移しても法線COM高・局所姿勢が同じ。
3. 水平yaw-only frameで、従来の加速度lean・世界姿勢が変わらない。
4. COM・ZMP・腕・支持域のWorld出力が世界へ戻っている。
5. 頭優先と追跡手の世界回転の所有権。
6. ゼロ／非有限frame、不正足目標で骨変換が漏れない。
7. 入れ子描画後の復元とカメラ不変。
8. 頭入力自体をbankした場合に、回転保持誤差0でもheadUpDotWorldが1未満になることを検出。
9. adhesionの無効ZMPと荷重比nullが世界復帰後も保たれる。

既存のN02・身体バランス・上下の25件も成功。実VRMの傾斜中の靴底・衣服・胸腰の輪郭は統合側と独立観察担当が別に確認する。

## 限界

- 足法線はbind基準のproxy。実メッシュの靴底の正確な接触・足首の解剖学的可動域の合格判定ではない。
- supportSoleOffsetMは法線方向の靴底厚み。傾斜中のworld minY差を厚みとして再利用しない。
- 支持域は足矩形proxy、COMは重み付き骨点であり、皮膚接触力や摩擦を解いていない。
- 回転中の支持点の角加速度・遠心成分は今回の運動モデルの対象外。雲の上での姿勢制約を満たしたことと、全身の動力学が解けたことを分ける。
- 予想以上の傾斜や骨格・衣服差では、数値上足が届いても見た目が破綻し得る。既定の控えめなpitch／bankから実VRMで比較する。
- 宙返り・背面・実XRift・Quest・他者同期は未確認。支持優先で頭位置が動くことをVR追跡と両立済みとは扱わない。
