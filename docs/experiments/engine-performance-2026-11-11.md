# エンジンの実行時の無駄を減らす（結果は変えない） / 2026-11-11

- 実行環境: ローカル自作骨格（fixture・detailed fixture に、どのソルバーも使わない髪やスカート相当の骨を足したもの）、Node v22.18、デスクトップ。ローカル実VRMの姿勢・PC XRift・Quest・他者視点では未計測（役割推定だけ手元VRM3体で再確認）。
- 対象: N02 1.0.0（profile・タグ・採用再現は不変）、作り込みの動作（charge-wave）、持ち物（pump-gun）、骨格の探索。
- 再現手順: `node --expose-gc scripts/bench-pose.mjs`（別のチェックアウトを測るときは `--root <path>`）、`npm test`（`tests/world-reads.test.mjs`・`tests/snapshots.test.mjs`）。

## きっかけ

ユーザーの依頼「ポーズエンジンの仕組みの改善最適化、軽量化をチェック」。点検の結果、重さよりも実行時の無駄が大きかった。そのうち **結果を変えないもの** だけを入れた（ユーザーの指示）。

点検で分かったこと（改善前、1体・1フレーム）:

- N02: 時間の 56% が three の `updateWorldMatrix` と行列の掛け算。`getWorldPosition`／`getWorldQuaternion`／`worldToLocal` は呼ぶたびに親をルートまで作り直し、`updateWorldMatrix(true,true)` は骨の下の部分木（髪・スカート・指）を全部作り直す。骨 62 本で行列の掛け算が 1 フレーム約 11,000 回。
- 作り込みの動作・持ち物: 腕の解法が時間の約 34%（腕1本につき毎フレーム約 78 通りの肘の向きを試し、候補ごとに数十個のベクトルを作る）、GC が 12〜17%。確保は 1 フレーム約 2.0MB／1.4MB。
- N02 の確保の約3割は、元の姿勢の控え（ドライバーと `applyNimbusPose` の中とで二重）。
- 探索（`inspectHumanoidRigs`）: 全スキンメッシュの全ボーンの名前を、毎回 正規表現で読み直す。

## 入れていないもの・未確認

- 結果が少し変わる改善は入れていない: 肘の向きの候補を減らす（全周 36 通りを毎フレームではなく数フレームに1回）、遠い・画面外のアバターは解く回数を減らす。
- N02 の残りの確保（約 300kB/フレーム）は `nimbus-pose.mjs` の作業用ベクトルと計測値の配列。作り込みの残り（約 540kB）は `Math.hypot`（V8 では確保する。`Math.sqrt` へ変えると最後の桁が変わりうる）とソルバー本体の作業用。
- コードの重さ: 筋斗雲アイテムは使わない肩車・伏せの支えを約 24kB 同梱している（入口が `src/index.mjs` 1つのため）。用途別の入口に分ければ落とせる。未着手。
- 描画フックの外し残り: `attachPoseDriver` の manager は自分が一番外側のときしか `scene.onBeforeRender` を外せない。置く・外すを繰り返すと空の層が残る。未着手。
- ローカル実VRMでの姿勢の一致、PC XRift、Quest、他者視点は未確認。Quest での時間は未計測（デスクトップの数倍の見込み）。
- アイテムへの反映は別の作業。写して使うアイテム（気功波・塩マシンガン）は `src/world.mjs` も写す必要がある。筋斗雲3種は N02 のタグ固定なので、反映するなら新しいタグを切る。
