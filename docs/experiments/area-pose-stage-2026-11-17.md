# エリアで当てる全身の動作（体操ステージ）と VR / 2026-11-13〜17

利用側アイテム items/motion-stage（体操ステージ、GitHub toM7x7/taisoustage）からのフィードバック。このリポジトリの `applyAuthoredPose`・`resolvedKeys`・`lerpFrame`・`selectActorRig` を写して使った。写しは items/ki-charge-orb の `src/pose-lib`（lab 6584877 ＋頭の向きの未コミット分）で、4f28544 の高速化は入っていない。

## 何を試したか

- 掴む・乗るなどの操作なしで、円いエリア（半径1.7m）に足元が入った人を全員当てる。持ち主1人ではなく、エリア内の全員（自分と他人）に当てる初めての使い方。
- 判定と時刻は各クライアントで決める：`useUsers` の位置をアイテムの座標へ直して円の中か調べ、拍は壁時計。通信なし。
- 動作：キー10個のオリジナルの体操（背伸び・腕振りと屈伸・体側・前屈と後屈）を 32拍×0.55秒でループ。`action`（入り→溜め→放ち）は使わず、キーだけの `ActionClip` を `resolvedKeys` に渡し、隣り合う2キーを `lerpFrame` で混ぜてループさせた。キーは訪れる順に並べた（腕の計画が前のキーの解を引き継ぐ）。
- 入り 0.45秒・解除 0.2秒の重み、入った時の向きからエリアの正面へ 0.8秒で向き直る（股関節から入った時の体の向きを読む）。
- VR の人の扱いを3通り用意：`skip`（当てない）、`body`（`preserveHands:true`、腕は追跡した手へ）、`full`（手も動作どおり）。VR ではどちらも `headMode:'host'`。

## 結果

| 確認 | 結果 |
|---|---|
| ローカル自作骨格（木製人形3体、検証ページ） | 入る→0.7秒で認識、1秒で全身・正面、出る→0.23秒で重み0・ホスト姿勢へ。3人が同じ姿勢（腰基準の左手 0mm 差）。1周で手の速さ最大 2.9m/s、単発の跳びなし。VR の `body` は手が本人の手の高さ（0.88〜0.92m）のまま腰が6cm沈み前屈で頭が31cm下がる、`full` は手も上がる（1.94m） |
| PC 実XRift | 明示の報告なし。VR の報告が「VRでも」なので PC でも当たったと読める（推定）。掴んでいない人に当てるのは、これまでのアイテム（持ち主だけ）と違う初めての使い方 |
| VR 実XRift（Quest） | 2026-11-17 ユーザー報告「VRでも反映出来ていました」（v3、`full`）。どの視点（本人の一人称・他人の画面）かの内訳は未報告 |
| 他者視点・複数人 | 未報告 |

分かったこと：

- **VR の人の体もアイテムの描画時の上書きで動く。** 公式 0.66.0 の型では、VR の体はホストが `PlayerMovement.vrTracking`（頭の yaw/pitch、アバター基準の両手、腰の移動量、足の動きの種類）から動かしている。本番で当たったので、ホストの VR の姿勢づけは `scene.onBeforeRender` より前に済んでいる（PC と同じ順）と見てよい。8章の「VRでは腕を上書きしない使い方を想定」は、実XRift では上書きもできると分かった（想定の変更ではなく、選べるようになった）。
- ヘッドセットの視界はアイテムから動かせない（WebXR）。頭の骨は `headMode:'host'` でヘッドセットの向きのままにした。
- 当てる対象は `selectActorRig` で他人も自分も同じように見つかった（`remote-player-<id>` の印の慣習は 2026-11-17 時点でも有効）。

## 未対応のアバター（2026-11-17 報告、原因未特定）

ユーザーから「また非対応アバターがあった」。コンソールの `[motion-stage] ... not posed` の行（`diagnosis`）はまだ受け取っていない。`selectActorRig` が当てない経路は次のとおりで、どれかを診断で切り分ける：

- `waiting-for-avatar` / `ambiguous-owner`：他人の `remote-player-<id>` の印が無い・2つある
- `no-avatar-near`：足元の近くにスキン付きの骨格が無い（スキンの無い剛体アバター、腰が足元から水平1.2m・高さ0.15〜2.6mの外：とても大きい／とても小さい体、原点のずれ）
- `unsupported`：名前で14役割が読めず、形からの推定も拒否（骨が14本未満、腕と脚の組が見つからない＝腕なし・獣型、腕や脚の候補が複数＝翼・尻尾・多腕、左右が決まらない、名前と形が食い違う、検査不合格）。名前の表で同じ順位の骨が2本ある（同じ役割の名前が重複）ときも名前では読めない
- `prepareRig` の例外（バインド姿勢から体の向きが作れない等）
- 当たったのに見た目が変わらない：ホストがそのアバターだけ描画の直前に骨を書き直す、別のスケルトンの複製を描いている
