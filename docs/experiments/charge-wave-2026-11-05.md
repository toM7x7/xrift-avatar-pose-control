# 溜めて放つ気功波のポーズ実験（2026-11-05）

ユーザー依頼「新規ポーズを作る機構として、両手で溜めて放つポーズを題材にポーズ編集の品質を上げる」。手だけでなく全身の姿勢が大事、という指示も受けた。既存の作品名を使わず、オリジナルの「charge-wave」として作った。仕組みは[AUTHORED_ACTIONS_V1](../specs/AUTHORED_ACTIONS_V1.md)。

## 入力

- 参考画（Codexの画像生成、木製デッサン人形）：[5段のポーズ](../concepts/2026-11-05/charge-wave-pose-sheet-v1.png)、[手の形](../concepts/2026-11-05/charge-wave-hands-v1.png)。構え・溜め・押し出し・残心と、玉を挟む手・押し出す手。
- 体：新しい詳細な自作骨格（上胸・鎖骨・指15本×2・つま先、標準／0.75倍／1.3倍）と、手元の実VRM3体（A01 標準・小柄寄り、A02 手足の重みが無いモデル、A03 別作者・太いズボン）。VRMと画像はコミットしない。
- ホストの姿勢：腕を下ろした待機＋頭の小さな揺れを毎フレーム戻してから当てる（描画トランザクションと同じ）。

v6で出た「前腕のねじれが±180°をまたいで肘が反転（8,000°/s）」は、空間上の最短補間が腕にとって逆ひねりの経路だったのが原因。v7の計画で、左腕の回り込み角は61〜82°の範囲に収まり、ねじれは−21°→+56°へ一方向に進む（反転なし）。

主な見つけ方の例：

- 左手（上の手）の指定が「指を上へ」だったため、肩から右腰へ斜め下に伸びる前腕に対して手首が120°以上折れていた（v0の手首−141°）。人が角度で探すのは難しく、組の向きのフィットで−37°へ。
- 両足が同時に浮いて支持多角形が空になり、画面が止まった（跳んでいた）。踏み替えを時間差にし、浮かす前に骨盤を軸足の上へ移す。片足立ち中の重心は別に記録する。
- 小柄なA01は腕が短く、両手が右腰に届かない。両手の目標を一緒に肩の方へ寄せ、接触を保つ（未達0mm）。

## 最終（v7）の残り

- 構えに入る速さ：0.65秒の入りで最大約2,000〜2,200°/s（上腕）。閾値1,400は仮。速くしたいかゆっくりにするかは体験で決める。
- 押し出しの0.16秒は意図して速い（`fastPhases.thrust`、閾値3,500）。自作骨格3,571、A02 3,938とわずかに超える。
- 指を外へ扇に開く押し出しは尺屈36°前後（閾値35）。
- A02は手足にスキンの重みが無く、胴と腿の当たりを比率で推定している。見た目の判定対象外。
- 自作骨格の写真：[キー5枚の正面・側面](../screenshots/charge-wave-fixture-keys-2026-11-05.png)。実VRMの撮影は`local-assets/studio/`（非公開）。

## v8：構えの磨き込みと骨格の互換（同日午後）

依頼：「筋斗雲のときのようなボーン非対応が起きているかも、幅広く対応して」「手首・腰の入れ方、放つときの手の位置と高さにこだわる」。

### ボーン非対応の正体

アイテムは`inspectHumanoidRigs`の名前の表（VRoid・Mixamo系）だけでアバターを探していた。手元のA02はBlender式の名前で、three.jsのGLTFLoaderが`.`を落とすため`upper_armL`・`forearmL`・`handL`・`upper_legL`として見える。名前の表では14役割のどれも読めず、構えが出ない（筋斗雲v4までと同じ）。

- `selectActorRig`（`./xrift`）：名前→読めなければ名前の流派＋骨格の形の推定（`resolveRoles`）。他人は印の中、自分は印の外。読めないときは理由と全ボーン名を返す。
- 自作骨格を21通りに作り直す`createDetailedPoseFixture(options)`と`npm run review:compat`：命名7流派＋名前なし・指／首／上胸／鎖骨／つま先の欠け・ねじれ骨（鎖の中／横）・-Z向き・骨軸の回転。**21/21で姿勢がつき、同じ骨格の15変種は基準と0.000mmで同じ姿勢。**
- Pose Studioの「骨の読み取り」：A02は「ボーン名＋骨格の形」で読め、VRM定義と同じ骨を選ぶ。A01・A03は名前で読める。
- つま先の骨が無い体で足の滑りを足首で測っていた（踏ん張りで5.9mm）。推定の母趾球で測るよう修正（0mm）。

| 足 | 前足[0.23,0.16]・後ろ足[−0.25,−0.22]42°外 | 前足[0.25,0.22]・後ろ足[−0.27,−0.27]46°外（広く長く） |
| 放つ | `push`（両手とも指が上）、胸の前0.6m | `flower`（手首を横に並べ、上の手は指が上・下の手は指が下、手のひらを前へ22°開く）、胸の高さ・前0.55m（ほぼ腕を伸ばす） |

| 入り・戻り | `weightIn`0.2、戻りは最初からホストへ混ぜる | `weightIn`0.3・中間キーは`outSine`、戻りは`inOutSine`で後半40%だけ混ぜる |

### 直した仕組み（どれも見えていた跳びの原因）

- 組の寄せがジグザグ：中央の組が左右の肩へ交互に寄り337mmも下がっていた → 超過量で重みづけた平均方向へまっすぐ下げる。
- 戻りで手首が5cm跳ぶ：手の基準点が途中で付け根→手のひら中心へ切り替わる → `pointMix`で混ぜて移る。
- ビームの出始めに脚が1コマで跳ぶ（240Hzで2,569°/s）：反動を25msで立ち上げる。
- 実VRMだけ戻りで腕が跳ぶ（4,965°/s）：休めのキーは腕がほぼ伸びていて肘の回り込みとねじれが入れ替え可能、独立に解くと任意の解（回り込み180°・回外85°）になる → キーを動作の通る順に前の解を引き継いで解く。
- 後ろ足の足首の横倒れ（28.8°）：かかとを上げた後ろ足を母趾球で腰の方へ回す（`pivot`）。足が腰の前へ出る途中で切り替わると1コマ跳ぶので、腰がどれだけ前にあるかで滑らかに効かせる。

A02は胴にスキンの重みが無く、胴の太さを比率で推定している（その推定にめり込む値）。頭の大きいちびキャラで、de Levaの体節質量（人の比率）で出す重心も当てにならない。撮影では手は腰の横・胸の前にあり、見た目の破綻は無い。数値は見た目の判定に使わない。

撮影はローカルのみ（`local-assets/compat/`、`items/ki-charge-orb/output/pose/tomo-*.png`）。アイテムの実機（XRift）では未確認。
