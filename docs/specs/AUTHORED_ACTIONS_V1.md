# 全身の動作を作る仕組み（authored actions v1）

乗り物の姿勢とは別に、「構える→溜める→放つ」のような全身の動作を、どの体格のアバターにも同じ意図で当てるための仕組みです。題材は両手で溜めて放つ気功波（[charge-wave.v1.json](../../specs/charge-wave.v1.json)）。既存の描画トランザクション（`attachPoseDriver`）にそのまま乗ります。

## 1. キーの書き方

キーは「骨の回転」ではなく「体の意図」で書きます。長さは身長1.65m・腰0.95mの基準体のメートル、角度は度、軸は体の向き基準（+X左・+Y上・+Z前）。実際の体には腰の高さで拡縮して当てます。

| 項目 | 意味 |
|---|---|
| `pelvis.offset / rot` | 腰の沈み・前後左右の移動、骨盤のヨー・前傾・横傾き |
| `torso.rot` | 胸の向き。背骨・胸・上胸の各骨へ骨盤から順に配分（`weights`で配分変更） |
| `head.mode` | `host`＝ホストの視線（PCのカメラ・VRのHMD）を保つ／`body`＝作者の向き。`neck`で首の分担 |
| `clavicles` | 鎖骨の前方突出・挙上（手を伸ばす・すくめる） |
| `feet` | 足の置き場所（地面上の足首の真下）、つま先の開き、かかとの持ち上げ（`heel`）。かかとを上げた後ろ足は母趾球を軸に腰の方へ回る（`pivot`、既定1、最大50°） |
| `knees.out` | 膝をつま先の向きからどれだけ外へ出すか（内股を防ぐ） |
| `hands.pair` | 両手の組。`clam`＝玉を上下の手のひらで挟む、`push`＝手のひらを前へ押し出す、`flower`＝手首を横に並べ、上の手の指は上・下の手の指は下で手のひらを前へ口のように開く（`open`・`lowerOpen`（下の手の開き、既定は`open`）・`gap`・`spread`・`upper`）。下の手は大きめに開く：指を真下・手のひらを前は人の腕では作れない |
| `elbows` | 肘の向きの好み（強制ではない） |
| `fingers` | 指ごとの曲げ・開き。`wrap:true`で玉の半径に沿って自動で曲げる |

両手の組（`pair`）は、接触点・半径・指の開きから左右の手の位置と向きを幾何で決めます。手のひらを前・指を上にすると親指は内側を向く（壁を押すときと同じ）ので、`push`は親指側の付け根同士を合わせます。`unit:"arm"`は中心のずれを腕の長さで拡縮します（単位は体のメートルのまま。腕の長さの倍数ではない）。

## 2. 解き方（`applyAuthoredPose`）

1. 骨盤の位置と回転 → 背骨の鎖へ回転を配分 → 鎖骨 → 首と頭（ホストの視線を保つ）。
2. 足を地面に固定。届かなければ骨盤を下げ、膝が深すぎれば上げる（`pelvisAutoDropMm`）。膝はつま先の向きへ。
3. 両手の接触を先に守る：どちらかの手が届かない体（腕が短い）では、両手の目標を一緒に寄せる（`pairShiftMm`）。届かない腕の方向を超過量で重みづけた平均へ下げるので、中央の組は左右の肩へジグザグせず胸の方へまっすぐ戻る。接触は崩さない。
4. 腕は肘の回り込み（swivel）を全周から探し、手首の屈伸・橈尺屈、前腕の回内外、肩の回旋（上腕のねじれ。腕を下ろして前腕を前へ折るのが0、外へ・上へが外旋、外旋90°・内旋75°）、皮膚の当たり（2cmまでのめり込みは軽く、深い分は上限付き）、肘の好み、前フレームとの連続性の合計が最小の肘を選ぶ。前腕の回内外は前腕の骨、残りは手首。手首の範囲を超える手の向きは、手首をねじらず範囲の端まで曲げて手の向きの方を譲る（`wristLimitedDeg`、`clampWrist:false`で従来どおり）。
5. 指は手の安静時の向きから曲げ・開く（ホストの指アニメーションに依存しない）。
6. 出入りはホストの姿勢と骨ごとに混ぜる（`weight`）。

## 3. タイムライン（`sampleAction`）

押した時刻・離した時刻・溜め量だけで決まる純関数なので、他人の画面でも同じ動きを再生できます。

- `enter`：ready→（`via`の中間キー）→gather。足が場所を変えるときは片足ずつ踏み替え、浮かす前に軸足へ体重を移す。
- `hold`：gather→chargeを溜め量に合わせて進め、呼吸の揺れを足す。
- `release`：thrust→beam（反動・震え。反動は25msで立ち上がる）→follow→ready（重みを0へ。`weightOut`を数値にすると戻りのその割合を過ぎてから混ぜ始める）。
- 手の移動は骨盤軸まわりの円柱座標で補間し、体の前を横切るときは外へふくらませる。
- 関節空間の計画：各キーを一度解いて前腕のねじれ・肘の回り込み・手首角を記録し、キー間はその値に沿わせる（遷移の中ほどほど強く従わせ、遅れて1コマで追いつく跳びを防ぐ）。空間上の最短補間が「逆ひねり」を要求して肘が反転するのを防ぐ。キーの姿勢そのものは変わらない。キーは動作が通る順（入り→溜め→放ち→戻り）に、前のキーの解を引き継いで解く（ほぼ伸びた腕では肘の回り込みとねじれが入れ替え可能なため）。2度通るキー（両端のready）は最初の解を使う。
- 手の基準点がキー間で違う（付け根→手のひら中心など）ときは、基準点のずれも混ぜて移る（`pointMix`）。手首は跳ばない。

## 4. 品質の検査（`evaluateAction`）

ホストの待機姿勢を毎フレーム戻しながら全タイムラインを60fpsで解き、各フレームの値と閾値（クリップの`quality`）で合否を出します。数値の検査であり、見た目や実機の合格ではありません。

| 指標 | 見るもの |
|---|---|
| 手首の伸展・屈曲・橈尺屈、前腕の回内外、残りのねじれ、肩の外旋・内旋、手首の範囲で譲った角度 | 関節の可動域 |
| 手の未達・手の向きの誤差 | 接触の正確さ（計画が手を導いている間は向きの誤差を数えない） |
| 腕と胴・腿の皮膚との隙間 | 実際のスキンから測った楕円断面（服の厚みも含む） |
| 膝・足首の背屈・横傾き・膝の内側入り | 下半身の無理 |
| 足の滑り | 地面に置いた足の母趾球の水平移動（踏み替え中は除く） |
| 重心の余裕 | de Levaの体節質量で重心を出し、両足の支持多角形からの距離（片足立ちは別に記録） |
| 首のひねり・関節の角速度・肘の回り込みの跳び | 不自然な速さや反転（意図した速い相は`fastPhases`で別の閾値） |

## 5. 作者の補助

- `fitPairAxes`：両手の組の向きだけを探索し、手首と前腕が楽で、作者の指定に近い向きを選ぶ（`npm run fit:charge-wave`、作者の値は`authoredAxes`に残す）。
- Pose Studio（`/studio.html`）：正面・側面・上・斜めの4画面、キーの残像、手の目標と玉、重心と支持多角形、胴と腿の当たり、フレームごとの数値、全フレーム検査とグラフ。キーのJSONをその場で編集。手元VRMはブラウザ内だけで読む。
- `npm run review:charge-wave`：自作骨格3体格＋短押しで検査し`artifacts/`へ保存。
- 作り方の手順は [.claude/skills/authored-pose/SKILL.md](../../.claude/skills/authored-pose/SKILL.md)（参考画像→キー→Studio→フィット→検査→互換→実VRM→記録→アイテムへ）。

## 6. いろいろなアバターで使う

XRiftアイテムは`selectActorRig`（`./xrift`）でアバターを見つけます。他人は`remote-player-<id>`の印の中（ホストの慣習）、自分はどの印にも入っていない骨格で、腰が足元の近くにあるもの。まずボーン名の表で読み、読めないときだけ名前の流派（Blender/Rigify・Mixamo・Unreal・VRChat/Cats・MMD など）と骨格の形から役割を推定します（`resolveRoles`）。食い違い・左右不明・検査不合格は当てずに`diagnosis`（理由・候補・全ボーン名）を返します。

- `npm run review:compat`：自作骨格を21通り（命名7流派＋名前なし、指・首・上胸・鎖骨・つま先の欠け、ねじれ骨、-Z向き、骨軸の回転）に作り直し、同じ入口で見つけて全タイムラインを解く。同じ骨格の変種は基準と同じ姿勢（0.01mm以内）であることを確かめる。
- Pose Studioの「骨の読み取り」：手元VRMをXRiftと同じ読み方で読めるか、VRM定義と同じ骨を選んだかを表示。

## 7. 境界

描画の姿勢だけを扱います。XRiftでの所有者の特定・同期・入力・カメラは利用側。VRでは手が追跡されるので、腕は`preserveHands`でホストの手へ届かせ、腕を上書きしない使い方を想定しています。剛体の接触や転倒を解く物理ではありません。
